# 0013. refresh 세션은 로그인당 한 행으로 두고 직전 토큰까지만 재사용을 탐지한다

- 상태: 채택
- 날짜: 2026-09-24

## 맥락

refresh token rotation은 토큰마다 행을 만들면 행이 갱신 횟수만큼 늘어납니다. 브라우저 탭이 동시에 갱신하면 정상 요청이 재사용으로 오판될 수 있습니다.

## 결정

- 로그인 한 번이 한 행입니다. 갱신하면 `previous ← current`, `current ← 새 해시`로 덮어씁니다.
- 직전 토큰이 교체 후 `policy.rotation-grace` 안에 오면 `409 TOKEN_ROTATED`로 재시도를 유도하고, 그 뒤에 오면 탈취로 보고 세션을 폐기합니다.
- 그보다 오래된 토큰은 탐지하지 않고 거부만 합니다.
- 세션은 PostgreSQL에 둡니다. 재시작해도 로그인이 유지됩니다.

## 검토한 대안

- 토큰마다 행(family 방식): 모든 과거 토큰의 재사용을 탐지하지만 행이 많이 늘어납니다.
- Redis: 인스턴스 한 대 규모에서는 운영 부담이 큽니다.

## 결과

- 행 수는 로그인 횟수 수준입니다. "로그인한 기기 목록" 기능에 그대로 쓸 수 있습니다.
- 관련 규칙: [SES](../domain.md#6-세션-규칙-ses)
