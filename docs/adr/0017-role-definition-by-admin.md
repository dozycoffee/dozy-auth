# 0017. role 정의는 admin이 관리 화면에서 등록한다

- 상태: 채택
- 날짜: 2026-09-24

## 맥락

서비스마다 새 role이 계속 생깁니다. 마이그레이션으로만 추가하면 Auth 배포가 필요합니다.

## 결정

- admin이 관리 API로 role을 등록합니다. 등록만으로는 권한이 생기지 않으므로 admin 권한으로 허용합니다.
- code는 등록 후 바꿀 수 없습니다. 서비스 코드가 문자열로 참조하기 때문입니다.
- system role은 마이그레이션으로만 만듭니다. audience 추가는 owner만 합니다.
- 서비스는 role을 코드에서 쓰기 전에 Auth에 먼저 등록합니다.

## 검토한 대안

- 서비스가 배포할 때 자동 등록: 서비스가 Auth 관리 권한을 가져야 합니다.

## 결과

- 등록과 배포 순서가 어긋나면 기능이 막힌 채 배포됩니다. 운영 절차로 관리합니다.
